# Quiz Bonus Features Design

## Goal
`e1-2` 브랜치의 현재 콘솔 퀴즈 게임에 보너스 과제 5개를 모두 추가한다.

대상 기능:
1. 랜덤 출제
2. 문제 수 선택
3. 힌트 기능
4. 퀴즈 삭제 기능
5. 점수 기록 히스토리

작업 원칙:
- 구현은 기능별 브랜치에서 진행한다.
- 브랜치 이름은 `feature/<topic>` 형태를 사용한다.
- 각 기능은 작은 단위 커밋으로 나눈다.
- 각 기능 브랜치는 완료 후 `e1-2`에 병합한다.
- `push origin`은 하지 않는다.

## Current State
현재 구현 상태:
- 메뉴: 퀴즈 풀기 / 퀴즈 추가 / 퀴즈 목록 / 점수 확인 / 종료
- `Quiz` 클래스: question, choices, answer
- `QuizGame` 클래스: 메뉴 흐름, 입력 검증, 저장/불러오기, 최고 점수 관리
- `state.json`: `quizzes`, `best_score`
- 보너스 과제 5개는 모두 미구현

## Design Summary
기존 구조를 유지하면서 `Quiz`와 `QuizGame`을 확장한다.

핵심 방향:
- 기존 콘솔 입력 흐름을 크게 깨지 않는다.
- 저장 포맷은 하위 호환적으로 확장한다.
- 각 보너스 기능은 독립 커밋으로 남길 수 있도록 구현 범위를 분리한다.

## Data Model Changes

### Quiz
기존 속성:
- `question`
- `choices`
- `answer`

추가 속성:
- `hint`

규칙:
- 기본 퀴즈에는 모두 힌트를 제공한다.
- 새 퀴즈 추가 시 힌트도 입력받는다.
- 저장 파일에 `hint`가 없더라도 기본값으로 처리해 기존 데이터도 읽을 수 있게 한다.

### State File
`state.json`은 다음 구조로 확장한다.

```json
{
  "quizzes": [
    {
      "question": "문제",
      "choices": ["선택지1", "선택지2", "선택지3", "선택지4"],
      "answer": 1,
      "hint": "힌트 문장"
    }
  ],
  "best_score": {
    "correct": 4,
    "total": 5,
    "score": 72
  },
  "history": [
    {
      "played_at": "2026-04-03T10:30:00",
      "total": 5,
      "correct": 4,
      "score": 72,
      "hint_used": 1
    }
  ]
}
```

규칙:
- `history`가 없으면 빈 목록으로 처리한다.
- 손상되었거나 구조가 틀리면 기존 복구 흐름처럼 기본 데이터로 복구한다.
- 날짜/시간은 ISO 8601 문자열로 저장한다.

## Feature Design

### 1. 랜덤 출제
퀴즈 시작 시 현재 퀴즈 목록을 복사한 뒤 랜덤으로 섞는다.

규칙:
- 원본 저장 순서는 바꾸지 않는다.
- 플레이 순서만 섞는다.
- 문제 수 선택 기능과 함께 동작할 수 있어야 한다.

구현 방향:
- `random.shuffle()` 사용
- 플레이용 목록을 별도로 만든다.

### 2. 문제 수 선택
퀴즈 시작 시 몇 문제를 풀지 입력받는다.

규칙:
- 최소 1문제, 최대 현재 보유 퀴즈 수
- 잘못된 입력은 기존 `ask_number()` 흐름으로 재입력 처리
- 선택 수만큼만 출제

구현 방향:
- 플레이 시작 전에 문제 수를 묻는다.
- 섞인 목록의 앞에서 선택한 개수만큼 사용한다.

### 3. 힌트 기능
각 문제마다 정답 입력 전에 힌트를 볼지 선택할 수 있게 한다.

규칙:
- 힌트는 문제당 최대 1번만 사용 가능
- 힌트를 쓰면 해당 문제 점수에 감점 적용
- 정답 수와 별도로 점수 계산에만 반영

점수 정책:
- 기본 점수는 `정답 수 / 전체 문제 수 * 100` 기반
- 힌트 1회당 10점 감점
- 최종 점수는 0점 미만으로 내려가지 않음

예시:
- 5문제 중 4개 정답 = 80점
- 힌트 2회 사용 = 20점 감점
- 최종 점수 = 60점

구현 방향:
- 문제 출력 후 `힌트 보기` 여부를 묻는다.
- 사용 시 힌트 문장을 출력하고 `hint_used` 카운트를 증가시킨다.
- 최고 점수 비교와 기록 저장은 감점 반영 점수를 기준으로 처리한다.

### 4. 퀴즈 삭제 기능
메뉴에 퀴즈 삭제 기능을 추가한다.

규칙:
- 목록 번호를 보고 삭제할 문제를 선택한다.
- 삭제 전 최종 확인을 받는다.
- 삭제 후 즉시 저장한다.
- 퀴즈가 없을 때는 안내 메시지를 출력한다.

구현 방향:
- 메뉴 항목을 1개 늘린다.
- 현재 목록을 보여주고 번호를 입력받아 삭제한다.
- 확인 입력은 문자 기반으로 처리한다 (`y/n` 또는 이에 준하는 단순 규칙).

### 5. 점수 기록 히스토리
플레이가 끝날 때마다 기록을 남긴다.

저장 항목:
- `played_at`
- `total`
- `correct`
- `score`
- `hint_used`

규칙:
- 매 플레이 종료 시 1건 저장
- 최고 점수는 계속 별도로 유지
- 점수 확인 메뉴에서 최고 점수와 최근 기록 목록을 함께 보여준다.
- 기록이 없으면 기존 메시지를 유지하거나 확장된 안내를 출력한다.

구현 방향:
- `history` 리스트를 `QuizGame` 속성으로 관리한다.
- 저장 시 전체 기록을 JSON에 반영한다.
- 출력은 최근 기록 중심으로 단순 텍스트 포맷을 사용한다.

## Menu and Flow Changes
기존 메뉴를 다음과 같이 확장한다.

1. 퀴즈 풀기
2. 퀴즈 추가
3. 퀴즈 목록
4. 퀴즈 삭제
5. 점수 확인
6. 종료

흐름 변경점:
- 퀴즈 추가: 힌트 입력 단계 추가
- 퀴즈 풀기: 문제 수 선택 → 랜덤 출제 → 힌트 사용 여부 확인 → 정답 입력 → 결과/기록 저장
- 점수 확인: 최고 점수 + 기록 히스토리 출력

## Error Handling
기존 예외 처리 기준을 유지하고 확장한다.

추가 대상:
- 힌트 입력 공백 방지
- 삭제 대상 번호 범위 검증
- 삭제 확인 입력 검증
- `history` 구조 검증
- `hint` 누락 데이터 보정

안전 종료 정책:
- `KeyboardInterrupt`, `EOFError`는 기존처럼 저장 후 안전 종료
- 플레이 중단 시 저장 가능한 상태만 저장하고 종료

## Branch and Commit Plan
브랜치는 `e1-2`에서 순차적으로 분기한다.

예상 브랜치:
- `feature/bonus-random-and-count`
- `feature/bonus-hint`
- `feature/bonus-delete`
- `feature/bonus-history`
- 필요 시 `feature/bonus-readme`

커밋 원칙:
- 기능 단위로 쪼갠다.
- 예: 모델 확장, 플레이 흐름 변경, 삭제 기능, README 반영, 테스트 보강
- 커밋 메시지는 현재 저장소 스타일에 맞춰 `feat:`, `docs:`, `test:` 등을 사용한다.

## Testing Strategy
필수 검증 항목:
- 랜덤 출제가 정상 동작하고 원본 저장 순서를 바꾸지 않는지
- 문제 수 선택 범위 검증이 되는지
- 힌트 사용 시 점수 감점이 반영되는지
- 삭제 후 `state.json`에 반영되는지
- 기록이 누적 저장되는지
- 기존 손상 파일 복구 흐름이 깨지지 않는지
- 재실행 후 퀴즈, 최고 점수, 히스토리가 유지되는지

가능하면 자동 테스트를 기존 `tests` 디렉터리에 추가한다. 콘솔 출력 중심 기능은 핵심 로직 단위 검증을 우선한다.

## Out of Scope
이번 변경에서는 다음은 제외한다.
- GUI 전환
- 외부 라이브러리 도입
- 데이터베이스 도입
- 멀티플레이
- 문제 카테고리 분리

## Success Criteria
다음이 충족되면 완료로 본다.
- 보너스 과제 5개가 모두 동작한다.
- `state.json`에 힌트/히스토리가 저장되고 재실행 후 유지된다.
- 각 기능이 별도 브랜치와 의미 있는 커밋으로 반영된다.
- 각 브랜치 작업이 `e1-2`에 병합된다.
- `push origin`은 수행하지 않는다.
