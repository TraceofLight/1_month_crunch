# 규칙 기반 정보 추출 및 감성 분석 시스템

고객 문의나 리뷰 문장에서 이메일, 전화번호, 날짜, 금액, URL을 정규표현식으로 추출하고, 한국어 감성 사전과 간단한 규칙으로 긍정/부정 점수를 계산한다. 형식이 명확한 정보는 높은 정밀도로 구조화하고, 감성은 토큰화, 사전 점수 합산, 부정어 반전, 강조어 가중치, 이중부정 처리로 해석 가능한 기준을 만든다.

규칙으로 언어 전체를 정의할 수는 없다. 이메일, 날짜, 금액처럼 표면 형식이 안정적인 정보는 규칙이 강하다. 반면 반어, 문맥 의존 표현, 복합 감성은 규칙이 쉽게 깨진다. 이 프로젝트는 그 차이를 코드와 평가 결과로 확인하는 데 초점을 둔다.

## 프로젝트 구조

| 경로 | 역할 |
| --- | --- |
| `src/rule_nlp/extraction.py` | 정규표현식 기반 정보 추출, 정규화, 개인정보 마스킹 |
| `src/rule_nlp/sentiment.py` | KNU 감성사전 로드, 도메인 단어 추가, 부정어/강조어 규칙 처리 |
| `src/rule_nlp/datasets.py` | 정보 추출 평가 50문장과 실패 사례 정의 |
| `src/rule_nlp/pipeline.py` | 데이터 다운로드, 평가 지표 계산, evidence 저장 |
| `scripts/run.py` | 전체 파이프라인 단일 실행 진입점 |
| `tests/` | 정규화, 감성 규칙, 지표, 데이터 구성 테스트 |
| `evidence/` | 실행 로그, 평가 지표, 오분류, 샘플 실행 결과 |

## 설치 및 실행

Python 3.10 이상에서 실행한다. 개발 및 검증은 Python 3.12 환경에서 수행했다.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python scripts/run.py --sample-size 200
```

단일 문장 분석:

```bash
python scripts/run.py --text "문의: support@company.co.kr, 전화 02-1234-5678, 일시: 2024년 3월 15일, 참가비: 50,000원. 서비스가 정말 좋지 않았어요."
```

테스트:

```bash
python -m pytest -q
```

도커 실행:

```bash
docker build -t rule-nlp .
docker run --rm rule-nlp
```

`scripts/run.py`는 처음 실행할 때 `data/` 아래로 KNU 감성사전과 NSMC 테스트 데이터를 내려받는다. `data/`는 원천 데이터 캐시이므로 버전 관리에서 제외했다. 재실행하지 않아도 결과를 확인할 수 있도록 실행 산출물은 `evidence/`에 보존했다.

## 정보 추출 규칙

정규표현식은 Python 내장 `re` 모듈만 사용했다. 모든 패턴은 `src/rule_nlp/extraction.py`에 의도와 매칭 범위를 주석으로 설명했다. 반환값은 패턴별 리스트이며 각 항목은 원문 `text`, 정규화된 `normalized`, 위치 `span`을 가진다.

| 패턴 | 처리 변형 | 정규화 |
| --- | --- | --- |
| 이메일 | `user@domain.com`, `user.name@sub.domain.co.kr`, `help+vip@shop.io`, 하이픈 도메인 | 소문자 이메일 문자열 |
| 전화번호 | `010-1234-5678`, `02-123-4567`, `031.1234.5678`, `(02) 987-6543`, `+82-10-5555-6666` | `0XX-XXXX-XXXX` 또는 `02-XXX-XXXX` 형식 |
| 날짜 | `2024년 1월 15일`, `2024/01/15`, `2024-01-15`, `2024.03.05` | ISO 8601 `YYYY-MM-DD` |
| 금액 | `10,000원`, `1억 2천만원`, `$100`, `2천5백원`, `15달러` | 정수값 |
| URL | `https://...`, `http://...`, `www.example.net/docs`, 쿼리 문자열 | `www.`는 `https://`를 붙이고 끝 문장부호 제거 |

정규식 문법 사용 지점:

| 문법 | 사용 예 | 목적 |
| --- | --- | --- |
| 메타문자 | `\d`, `.`, `[]`, `|` | 숫자, 임의 구분자, 문자 집합, 대안 표현 |
| 수량자 | `+`, `*`, `{1,2}`, `{3,4}` | 도메인 반복, 월/일 자리 수, 전화번호 중간 자리 수 제어 |
| 그룹 | `(?:...)`, `(?P<name>...)` | 캡처가 필요 없는 묶음과 날짜의 연/월/일 이름 캡처 구분 |
| 경계 조건 | `(?<!...)`, `(?!...)` | 이메일/전화번호가 더 긴 문자열 일부로 잘못 잡히지 않게 제한 |
| 후처리 | `datetime.date`, 단위 사전 | 유효하지 않은 날짜 제외, `억/천만/만/천/백` 금액 단위 환산 |

샘플 입력의 추출 결과는 `evidence/sample_run.json`에 저장되어 있다.

```text
입력: 문의: support@company.co.kr, 전화 02-1234-5678, 일시: 2024년 3월 15일, 참가비: 50,000원. 링크 https://www.example.com/path?q=1 ...

이메일: support@company.co.kr
전화번호: 02-1234-5678
날짜: 2024-03-15
금액: 50000
URL: https://www.example.com/path?q=1
```

보너스 개인정보 마스킹도 구현했다.

| 원문 | 마스킹 |
| --- | --- |
| `900101-1234567` | `900101-1******` |
| `1234-5678-9012-3456` | `1234-****-****-3456` |
| `010-1234-5678` | `010-****-5678` |

## 감성 분석 규칙

분석 흐름:

1. 정규식 토큰화로 한글/영문/숫자 토큰을 분리한다.
2. KNU 사전과 도메인 사전에서 토큰 또는 어간 점수를 찾는다.
3. 기본 점수를 합산한다.
4. 감성 단어 주변 2토큰 이전, 3토큰 이후에서 부정어를 찾는다.
5. 부정어 개수가 홀수면 점수 부호를 반전하고, 짝수면 이중부정으로 보고 원래 극성을 유지한다.
6. 감성 단어 앞 2토큰 안에 강조어가 있으면 가중치를 곱한다.
7. 총점이 양수면 긍정, 음수면 부정, 0이면 중립으로 판정한다. NSMC 이진 평가에서는 중립을 부정으로 매핑했다.

주요 규칙:

| 유형 | 표현 | 효과 |
| --- | --- | --- |
| 부정어 | `안`, `못`, `않`, `없`, `아니` 계열 | 주변 감성 점수 부호 반전 |
| 강조어 | `매우`, `정말`, `너무`, `아주`, `완전`, `굉장히`, `진짜`, `대단히`, `엄청`, `몹시` | 1.4~1.6배 가중 |
| 이중부정 | `좋지 않은 것은 아니다` | 부정어 2개이므로 원래 긍정 유지 |
| 과매칭 방지 | 강조어 자체는 감성 단어로 세지 않음, `정도→정` 같은 한 글자 과매칭 차단 | 사전 기반 오탐 감소 |

샘플 감성 계산:

```text
문장: 서비스가 정말 좋지 않았어요
토큰: [서비스가, 정말, 좋지, 않았어요]
감성 단어: 좋(+2)
강조어: 정말, 1.5배
부정어: 않았어요, 부호 반전
계산: +2 * 1.5 * -1 = -3.0
판정: 부정
```

## 평가 결과

평가 명령:

```bash
python scripts/run.py --sample-size 200
```

실행 일시: 2026-05-25, Python 3.12  
근거 파일: `evidence/run_summary.txt`, `evidence/extraction_metrics.json`, `evidence/sentiment_metrics.json`, `evidence/sentiment_errors.json`, `evidence/sample_run.json`

### 정보 추출 평가

50개 직접 작성 문장을 사용했다. 각 패턴별 10문장 이상, 각 패턴별 3가지 이상의 표기 변형을 포함했다. 지표는 정규화 결과의 정확 일치를 기준으로 계산했다.

| 패턴 | 문장 수 | TP | FP | FN | 정밀도 | 재현율 | F1 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 이메일 | 10 | 10 | 0 | 0 | 1.0000 | 1.0000 | 1.0000 |
| 전화번호 | 10 | 10 | 0 | 0 | 1.0000 | 1.0000 | 1.0000 |
| 날짜 | 10 | 10 | 0 | 0 | 1.0000 | 1.0000 | 1.0000 |
| 금액 | 10 | 10 | 0 | 0 | 1.0000 | 1.0000 | 1.0000 |
| URL | 10 | 10 | 0 | 0 | 1.0000 | 1.0000 | 1.0000 |

성공한 이유는 평가 문장이 규칙 설계 범위 안에 있기 때문이다. 이메일은 ASCII 로컬 파트와 도메인, 전화번호는 국내 지역번호/휴대전화/국제 표기, 날짜는 절대 날짜, 금액은 숫자와 통화 단위가 있는 표현만 목표로 잡았다. 이 범위에서는 규칙 기반 방식이 높은 정밀도와 해석 가능성을 보인다.

### 감성 분석 평가

NSMC `ratings_test.txt`에서 무작위 시드 42로 긍정 100개, 부정 100개를 균형 샘플링했다. 사전 점수만 합산한 기준선과 부정어/강조어/이중부정 규칙을 적용한 결과를 비교했다.

| 방식 | 표본 수 | 정확도 | 정밀도 | 재현율 | F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 사전 점수 합산만 사용 | 200 | 0.6850 | 0.7761 | 0.5200 | 0.6228 |
| 부정어/강조어/이중부정 규칙 적용 | 200 | 0.6900 | 0.7714 | 0.5400 | 0.6353 |

규칙 적용 후 정확도는 0.005, F1은 0.0125 상승했다. 큰 개선은 아니지만 `좋지 않다`, `나쁘지 않다`, `정말 좋지 않았다`처럼 표면 규칙으로 처리 가능한 문장에서는 점수 방향과 강도가 더 타당해졌다. NSMC 리뷰는 띄어쓰기 오류, 은어, 짧은 감탄, 영화 맥락 의존 표현이 많아서 단순 토큰화와 사전 합산만으로는 재현율이 낮다.

| 정보 추출 | `01012345678` | 구분자 없는 전화번호는 카드번호/주민번호와 충돌 위험이 있어 제외했다. | 신뢰도 점수와 문맥 단서가 있을 때만 허용 |

## 규칙 기반 접근법 분석

장점:

- 정밀도가 높다. 이메일, 날짜, 전화번호처럼 문법이 좁은 정보는 어떤 패턴 때문에 추출됐는지 바로 설명할 수 있다.
- 정규화가 명확하다. `2024년 3월 15일`을 `2024-03-15`로, `1억 2천만원`을 `120000000`으로 바꾸는 후처리 규칙을 직접 통제할 수 있다.
- 개인정보 마스킹처럼 실수 비용이 큰 영역에서 보수적 정책을 적용하기 쉽다.

단점:

- 재현율이 규칙 작성 범위에 묶인다. `공일공`, `백만원`, `다음 주 금요일` 같은 표현은 사람이 쉽게 이해하지만 규칙이 없으면 실패한다.
- 유지보수 비용이 증가한다. 새 도메인, 새 단위, 새 은어가 생길 때마다 예외와 후처리를 추가해야 한다.
- 감성은 문맥 의존성이 강하다. 부정어와 강조어는 국소 규칙으로 처리할 수 있지만 반어, 복합 감성, 주제별 평가 기준은 단순 합산으로 어렵다.

TF-IDF와 코사인 유사도를 쓰는 통계 기반 접근은 대량 문서의 유사도 검색, 카테고리 분류, 자주 등장하는 패턴 학습에 적합하다. 그러나 `이메일 주소를 추출하라`, `전화번호를 하이픈 형식으로 통일하라` 같은 정확한 구조화 요구에는 정규표현식이 더 직접적이다. 반대로 감성 분석처럼 표현이 다양하고 문맥이 중요한 문제는 통계 기반 또는 학습 기반 모델이 더 넓은 재현율을 낼 가능성이 높다. 실무에서는 정규식으로 확실한 엔티티를 먼저 추출하고, 분류나 감성처럼 불확실성이 큰 단계는 통계 모델과 결합하는 하이브리드 구성이 적합하다.

## 개인정보 처리 및 운영상 주의

추출기는 원문에서 연락처와 주민등록번호, 카드번호 같은 개인정보 후보를 찾을 수 있다. 운영 환경에서는 다음 기준을 둔다.

- 로그에는 원문 대신 `mask_personal_info()` 결과를 저장한다.
- 구분자 없는 긴 숫자는 카드번호, 전화번호, 주문번호가 충돌할 수 있으므로 문맥 없이 자동 확정하지 않는다.
- 정규식 결과는 후보 정보로 다루고, 외부 전송 전에는 마스킹 또는 별도 권한 검사를 거친다.
- KNU/NSMC 원천 데이터는 `data/`에 캐시하고, 재배포나 상용 사용 전에는 각 원 저장소의 사용 조건을 다시 확인한다.

## 문제 해결

| 증상 | 확인 및 조치 |
| --- | --- |
| `ModuleNotFoundError: rule_nlp` | 저장소 루트에서 실행한다. 테스트는 `pytest.ini`의 `pythonpath = src`를 사용한다. |
| KNU 또는 NSMC 다운로드 실패 | 네트워크 연결을 확인하고 `python scripts/run.py --sample-size 200`을 다시 실행한다. 이미 받은 파일은 `data/`에 캐시된다. |
| 감성 평가 수치가 README와 다름 | `--sample-size`와 샘플링 시드가 달라졌는지 확인한다. 기본 실행은 `--sample-size 200`, 시드 42다. |
| 이메일 뒤 한글 조사가 붙으면 누락됨 | 현재 구현은 ASCII 경계 조건으로 보정되어 있다. `python -m pytest tests/test_extraction.py::test_email_boundary_allows_korean_sentence_suffix -q`로 회귀 테스트를 확인한다. |
| 결과가 너무 보수적으로 보임 | 정규식은 고정밀 후보 추출을 목표로 설계했다. 재현율을 높이려면 한글 숫자, 상대 날짜, 구분자 없는 전화번호 같은 확장 규칙을 추가한다. |

## 개선 아이디어

- 한글 숫자와 상대 날짜 파서 추가: `공일공`, `백만원`, `다음 주 금요일`을 구조화한다.
- 형태소 분석기 연동: 단순 접미사 제거 대신 품사 기반으로 감성 단어와 부정 범위를 찾는다.
- Aspect 기반 감성 분석: `음식은 맛있는데 가격이 비싸요`를 `음식=긍정`, `가격=부정`으로 분리한다.
- 규칙과 통계 모델 결합: 정규식으로 확실한 엔티티를 추출하고, 감성은 TF-IDF/로지스틱 회귀 또는 Transformer 모델과 비교한다.
- 임계값과 중립 처리 개선: 현재 NSMC 이진 평가는 중립을 부정으로 매핑한다. 실무에서는 중립/검토 필요 라벨을 별도로 두는 편이 안전하다.
