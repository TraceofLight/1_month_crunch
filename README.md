# 1_month_crunch

## 1. 프로젝트 개요

Python 콘솔에서 동작하는 퀴즈 게임을 구현한 프로젝트입니다.

- 파이썬 기초 문법을 주제로 기본 퀴즈 6문항을 제공합니다.
- 메뉴 기반으로 퀴즈 풀기, 퀴즈 추가, 퀴즈 목록, 최고 점수 확인 기능을 제공합니다.
- `state.json`에 퀴즈와 최고 점수를 UTF-8로 저장하여 재실행 후에도 데이터가 유지됩니다.
- `KeyboardInterrupt`, `EOFError`, 손상된 JSON 파일을 처리하여 비정상 종료 없이 복구 가능하도록 구성했습니다.

## 2. 퀴즈 주제와 선정 이유

### 퀴즈 주제
- Python 기초 문법

### 선정 이유
- 이번 과제의 핵심이 Python 기본 문법, 클래스, 파일 입출력을 직접 구현하는 것이어서 문제를 푸는 과정 자체가 복습이 되도록 주제를 맞췄습니다.
- 변수, 자료형, 함수, 조건문, 예외 처리처럼 과제에서 실제로 사용한 개념을 문제로 다시 확인할 수 있게 구성했습니다.

## 3. 실행 환경

- Python 3.10+
- Standard Library only
- Windows 11 / Git Bash 기준으로 확인

## 4. 실행 방법

```bash
python main.py
```

실행 시 아래 메뉴가 출력됩니다.

1. 퀴즈 풀기
2. 퀴즈 추가
3. 퀴즈 목록
4. 점수 확인
5. 종료

## 5. 기능 목록

### 퀴즈 풀기
- 저장된 모든 퀴즈를 순서대로 출제합니다.
- 각 문제마다 1~4 사이의 정답 번호를 입력받습니다.
- 정답/오답을 바로 알려주고, 종료 시 최종 점수를 계산합니다.
- 최고 점수보다 높으면 `best_score`를 갱신합니다.

### 퀴즈 추가
- 문제, 선택지 4개, 정답 번호를 입력받아 새 퀴즈를 등록합니다.
- 등록 직후 `state.json`에 저장합니다.

### 퀴즈 목록
- 현재 저장된 전체 퀴즈 개수와 문제 목록을 출력합니다.

### 점수 확인
- 최고 점수가 있으면 점수와 정답 개수를 보여줍니다.
- 아직 플레이 기록이 없으면 안내 메시지를 출력합니다.

### 입력 예외 처리
- 빈 입력, 문자 입력, 허용 범위를 벗어난 숫자를 안내 메시지와 함께 다시 입력받습니다.
- `Ctrl+C`, `EOFError` 발생 시 저장 후 안전하게 종료합니다.

## 7. 데이터 파일 설명

- 경로: `./state.json`
- 역할: 퀴즈 목록과 최고 점수를 저장하는 프로젝트 루트 데이터 파일
- 인코딩: UTF-8

### 스키마

```json
{
  "quizzes": [
    {
      "question": "문제",
      "choices": ["선택지1", "선택지2", "선택지3", "선택지4"],
      "answer": 1
    }
  ],
  "best_score": {
    "correct": 4,
    "total": 6,
    "score": 66
  }
}
```

### 현재 구조를 이렇게 설계한 이유
- `quizzes`는 문제 목록 전체를 한 번에 저장하기 위해 배열 구조로 두었습니다.
- 각 퀴즈는 `question`, `choices`, `answer` 세 필드만 가지도록 최소 구조로 설계했습니다.
- `choices`를 배열로 저장하면 출력 순서 유지가 쉽고, 정답 번호(`answer`)를 1~4 범위의 정수로 관리하기 편합니다.
- `best_score`는 최고 기록만 저장하면 되므로 별도 배열이 아니라 단일 객체로 유지했습니다.
- 초기 상태에서는 플레이 기록이 없을 수 있으므로 `best_score`는 `null`이 될 수 있습니다.

## 9. 클래스 구조와 역할 분리 설명

### `Quiz` 클래스
- 개별 퀴즈 1개를 표현하는 데이터 단위입니다.
- 문제(`question`), 선택지(`choices`), 정답(`answer`)를 속성으로 가집니다.
- 퀴즈 출력(`display`), 정답 판정(`is_correct`), JSON 저장용 변환(`to_dict`, `from_dict`)을 담당합니다.

### `QuizGame` 클래스
- 게임 전체 흐름을 관리하는 상위 클래스입니다.
- 퀴즈 목록, 최고 점수, 실행 상태, 파일 경로를 관리합니다.
- 메뉴 표시, 입력 처리, 퀴즈 진행, 퀴즈 추가, 목록 조회, 점수 확인, 파일 저장/불러오기, 안전 종료를 담당합니다.

### 클래스로 분리한 이유
- 퀴즈 1개 자체의 책임과 게임 전체 흐름의 책임을 분리하기 위해서입니다.
- 만약 함수만으로 모두 구현하면 데이터 단위와 게임 상태가 섞여서 수정 범위가 커지고, 저장/출력/판정 로직을 재사용하기도 불편해집니다.
- 클래스로 나누면 `Quiz`는 “문제 한 개”, `QuizGame`은 “전체 게임 진행”이라는 역할이 분명해집니다.

## 10. 입력 처리 / 게임 진행 / 저장-불러오기 흐름 설명

### 입력 처리 기준
- `ask_text()`는 빈 문자열을 허용하지 않고 재입력을 요구합니다.
- `ask_number()`는 공백 제거 후 정수 변환을 시도하고, 실패하거나 허용 범위를 벗어나면 안내 메시지를 출력한 뒤 재입력을 요구합니다.
- `read_input()`는 `KeyboardInterrupt`, `EOFError`를 직접 받아 `SafeExit` 예외로 변환합니다.

### 게임 진행 흐름
1. `QuizGame().run()`으로 시작합니다.
2. `show_menu()`로 메뉴를 출력합니다.
3. `ask_number()`로 메뉴 번호를 입력받습니다.
4. `handle_menu()`가 선택한 기능에 따라 퀴즈 풀기/추가/목록/점수 확인/종료를 분기합니다.
5. 퀴즈 풀기 후에는 결과를 계산하고 최고 점수를 갱신합니다.

### 저장/불러오기 흐름
- 프로그램 시작 시 `__init__()`에서 `load_state()`를 호출합니다.
- `state.json`이 있으면 JSON을 읽어서 퀴즈 목록과 최고 점수를 복원합니다.
- 파일이 없으면 기본 퀴즈 데이터로 시작합니다.
- 파일이 손상되었거나 읽기/쓰기 중 오류가 발생하면 안내 메시지를 출력하고 기본 데이터로 복구합니다.
- 퀴즈 추가, 퀴즈 종료, 안전 종료, 퀴즈 플레이 후 점수 갱신 시 `save_state()`를 호출합니다.

## 11. 예외 처리 설명

### `Ctrl+C` / `EOFError` 안전 종료
- 사용자가 실행 중 `Ctrl+C`를 누르거나 입력 스트림이 종료되면 `read_input()`에서 `SafeExit` 예외를 발생시킵니다.
- `run()` 메서드는 이 예외를 받아 `handle_safe_exit()`를 호출합니다.
- `handle_safe_exit()`는 안내 메시지를 출력하고 `save_state()`를 호출한 뒤 종료합니다.
- 즉, 비정상 종료처럼 보이는 상황에서도 저장 가능한 범위까지 저장하고 안전하게 프로그램을 마칩니다.

### 파일 입출력에서 `try/except`가 필요한 이유
- JSON 파일은 파일이 없을 수도 있고, 깨진 형식일 수도 있으며, 읽기/쓰기 중 OS 오류가 날 수도 있습니다.
- 예외 처리가 없으면 프로그램이 바로 중단되어 사용자 경험이 나빠집니다.
- 따라서 `load_state()`와 `save_state()`에 `try/except`를 두어, 오류 시 기본 데이터 복구 또는 안내 메시지 출력이 가능하도록 했습니다.

## 15. JSON 사용 이유와 한계

### JSON을 사용한 이유
- Python 표준 라이브러리만으로 쉽게 읽고 쓸 수 있습니다.
- 사람이 파일 내용을 직접 확인하기 쉽습니다.
- 퀴즈 목록과 최고 점수처럼 구조화된 데이터를 저장하기 적합합니다.

### JSON 형식의 특징
- 키-값 기반 구조라서 객체와 배열 표현이 쉽습니다.
- 문자열, 숫자, 배열, 객체 등 기본 데이터 구조를 그대로 담기 좋습니다.
- 텍스트 기반이라 디버깅과 확인이 편합니다.

### JSON의 한계
- 동시 수정 충돌 관리가 어렵습니다.
- 데이터가 많아질수록 검색/수정 효율이 떨어질 수 있습니다.
- 스키마 강제가 없어서 잘못된 형식이 들어갈 수 있으므로 검증 로직이 필요합니다.

## 16. 심층 인터뷰 대비 설명

### 데이터 파일이 손상되면 어떻게 복구하는가?
- `load_state()`에서 JSON 파싱이나 구조 검증 중 예외가 발생하면 안내 메시지를 출력합니다.
- 이후 기본 퀴즈 데이터와 `best_score = None` 상태로 초기화합니다.
- 바로 `save_state()`를 호출해 복구된 기본 상태를 다시 파일에 저장합니다.

### 요구사항이 바뀌면 어디를 수정해야 하는가?
- 퀴즈 선택지를 5개 이상으로 늘리려면 `Quiz.from_dict()` 검증 조건, `build_default_quizzes()`, `add_quiz()` 입력 흐름, `display()` 출력 형식을 함께 수정해야 합니다.
- 최고 점수 대신 전체 기록 히스토리를 저장하려면 `best_score` 구조 대신 기록 배열을 도입하고 `save_state()`, `load_state()`, `show_best_score()`를 함께 수정해야 합니다.
- 힌트 기능을 넣으려면 `Quiz` 속성 확장, 퀴즈 출력/입력 로직, 점수 계산 로직을 함께 수정해야 합니다.

### 함수만으로 구현했다면 어떤 한계가 있는가?
- 데이터와 상태가 여러 함수에 흩어져 관리되기 쉬워집니다.
- 퀴즈 1개와 게임 전체 흐름의 책임이 섞이면서 수정 범위가 커집니다.
